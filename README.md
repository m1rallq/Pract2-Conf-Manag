## 1. Описание

Консольная программа (CLI), которая строит граф зависимостей пакета
Python (pip). Готовые менеджеры пакетов и библиотеки для получения
зависимостей не используются — только стандартная библиотека Python
(`urllib`, `json`, `re`, `argparse`, `collections`).

### Этапы

- **Этап 1. Минимальный прототип с конфигурацией** — параметры
  командной строки и их проверка с понятными сообщениями об ошибках.
- **Этап 2. Сбор данных** — получение прямых зависимостей пакета
  из репозитория PyPI по URL.
- **Этап 3. Основные операции** — построение полного графа
  зависимостей (с транзитивными) обходом в ширину (BFS) без рекурсии,
  с учётом максимальной глубины, фильтра по подстроке и циклических
  зависимостей; режим тестового репозитория.

## 2. Как это работает

### Получение прямых зависимостей (этап 2)

1. Программа запрашивает описание пакета через JSON API репозитория:
   `<URL>/<пакет>/json`, например `https://pypi.org/pypi/requests/json`.
2. Из ответа берётся поле `info.requires_dist` — список строк вида
   `idna<4,>=2.5` или `PySocks>=1.5.6; extra == "socks"`.
3. Каждая строка разбирается (формат PEP 508): имя пакета, ограничение
   версии, условие установки (маркер).
4. Зависимости с маркером `extra == ...` пропускаются: pip ставит их
   только по запросу (`pip install requests[socks]`).
5. Имена приводятся к единому виду (`Charset_Normalizer` →
   `charset-normalizer`), повторы убираются.

### Построение графа (этап 3)

Граф хранится как список смежности: «пакет → его зависимости».
Обход в ширину (BFS) идёт **без рекурсии**, через очередь
`collections.deque`:

```
очередь = [корень]; глубина[корень] = 0
пока очередь не пуста:
    пакет = очередь.взять_первый()
    если глубина[пакет] >= max_depth: пометить «не раскрыт», дальше
    для каждой прямой зависимости пакета:
        если имя содержит подстроку фильтра: пропустить
        добавить связь пакет -> зависимость
        если зависимость ещё не встречалась:
            глубина[зависимость] = глубина[пакет] + 1
            положить её в конец очереди
```

- **Транзитивность.** В очередь попадают зависимости зависимостей,
  поэтому в граф входит всё, что понадобится для установки.
- **Максимальная глубина** (`--max-depth`). Корень — глубина 0,
  прямые зависимости — 1. Пакеты на предельной глубине попадают в граф,
  но их зависимости не запрашиваются (они помечаются «не раскрыт»).
  `-d 1` — только прямые зависимости.
- **Фильтр** (`--filter`). Пакеты, имя которых содержит подстроку
  (без учёта регистра), не учитываются: они не попадают в граф и их
  зависимости не обходятся. Список исключённых выводится в конце.
- **Циклы.** Каждый пакет раскрывается один раз (словарь `глубина`
  хранит уже встреченные), поэтому цикл A → B → C → A не приводит
  к бесконечному обходу. После построения графа циклы находятся
  обходом в глубину без рекурсии (вершины «на пути» и «обработанные»)
  и выводятся отдельно, включая петлю A → A.
- **Ошибки в середине графа.** Если не удалось получить зависимости
  какого-то пакета (не найден на PyPI, не описан в тестовом файле),
  обход не прерывается: пакет остаётся в графе с пометкой об ошибке.
  Ошибка самого анализируемого пакета останавливает программу.
- **Кэш.** Каждый пакет запрашивается у PyPI один раз, даже если
  от него зависят несколько пакетов.

### Модули

| Файл | Назначение |
|---|---|
| `src/main.py` | точка входа, коды выхода |
| `src/cli.py` | параметры командной строки и их проверка |
| `src/pypi_client.py` | запрос к репозиторию PyPI (urllib) |
| `src/requirements.py` | разбор строк зависимостей |
| `src/local_repo.py` | чтение файла тестового репозитория |
| `src/collector.py` | источник данных (PyPI или файл) и сборка графа |
| `src/graph.py` | BFS без рекурсии, глубина, фильтр, поиск циклов |
| `src/report.py` | текстовый вывод графа |

## 3. Параметры

| Параметр | Что задаёт | По умолчанию |
|---|---|---|
| `-p`, `--package ИМЯ` | имя анализируемого пакета (обязательный) | — |
| `-r`, `--repo URL_ИЛИ_ФАЙЛ` | URL репозитория или путь к файлу тестового репозитория | `https://pypi.org/pypi` |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием (файлом) | выключен |
| `-a`, `--ascii-tree` | вывод в виде ASCII-дерева (используется с этапа 5) | выключен |
| `-d`, `--max-depth N` | максимальная глубина анализа зависимостей | `10` |
| `-f`, `--filter ПОДСТРОКА` | не учитывать пакеты, имя которых содержит подстроку | нет |

### Ошибки

| Где | Ошибка |
|---|---|
| `--package` | не указан; пустой; недопустимые символы; в тестовом режиме — не большие латинские буквы |
| `--repo` | обычный режим — не `http://` / `https://`; тестовый режим — не указан или файла нет |
| `--ascii-tree`, `--test-mode` | передано значение (это флаги) |
| `--max-depth` | не целое число; меньше 1 |
| `--filter` | пустая строка |
| репозиторий | пакет не найден (HTTP 404); нет связи; ответ не в формате PyPI |
| тестовый файл | неверный формат строки; имя не из больших букв; пакет описан дважды; анализируемого пакета нет в файле |

## 4. Тестовый репозиторий

Файл, где пакеты называются большими латинскими буквами, `#` — комментарий.
Одна строка — пакет и его зависимости через пробел:

```
A: B C
B: D
C: D E
D:
E:
```

| Файл | Что демонстрирует |
|---|---|
| `test_repos/simple.txt` | транзитивные зависимости; D достижим двумя путями, но в графе один раз |
| `test_repos/deep.txt` | цепочка A → B → C → D → E → F для проверки `--max-depth` |
| `test_repos/filter.txt` | пакеты `XB`, `XD` для проверки `--filter X` |
| `test_repos/cycle.txt` | цикл A → B → C → A |
| `test_repos/self_loop.txt` | петля A → A и цикл B ↔ C |
| `test_repos/missing.txt` | зависимость Z, не описанная в файле |
| `test_repos/broken.txt` | ошибка формата в строке 3 |

## 5. Запуск и тесты

Нужен Python 3.9+, сторонние библиотеки не нужны.

```bash
./run.sh -p A -t -r test_repos/simple.txt    # граф из тестового репозитория
./run.sh -p requests                         # граф пакета из PyPI
./run.sh -p flask -d 2 -f jinja              # глубина 2, без пакетов с "jinja"
./run.sh -h                                  # справка по параметрам
./run.sh test                                # запуск тестов
bash scripts/demo_graph.sh                   # этап 3 на тестовых репозиториях
bash scripts/demo_deps.sh                    # примеры с реальным PyPI
bash scripts/demo_errors.sh                  # примеры всех ошибок
```

В Windows без Git Bash: `run.bat -p A -t -r test_repos\simple.txt`,
`run.bat test`.

Тесты не требуют интернета: запросы к PyPI проверяются на локальном
HTTP-сервере с сохранёнными ответами (`tests/fixtures/pypi`).
Если интернета нет и на демонстрации, можно запустить такой сервер
вручную: `bash scripts/fake_pypi.sh`, а затем
`./run.sh -p requests -r http://localhost:8000/pypi`.

Транзитивные зависимости:

```
$ ./run.sh -p A -t -r test_repos/simple.txt

Пакеты по уровням (порядок обхода BFS):
  уровень 0: A
  уровень 1: B, C
  уровень 2: D, E

Зависимости:
  A -> B, C
  B -> D
  C -> D, E
  D -> —
  E -> —

Циклические зависимости:
  не найдены

Итого: пакетов 5, связей 5
Исключены фильтром: —
Не раскрыты из-за глубины: —
```

Циклическая зависимость:

```
$ ./run.sh -p A -t -r test_repos/cycle.txt
...
Зависимости:
  A -> B
  B -> C
  C -> A, D
  D -> —

Циклические зависимости:
  A -> B -> C -> A
```

Ограничение глубины:

```
$ ./run.sh -p A -t -r test_repos/deep.txt -d 2
...
Зависимости:
  A -> B
  B -> C
  C -> ... (не раскрыт: достигнута глубина)
...
Не раскрыты из-за глубины: C
```

Фильтр:

```
$ ./run.sh -p A -t -r test_repos/filter.txt -f X
...
Зависимости:
  A -> B, C
  B -> D
  C -> D
  D -> —
...
Исключены фильтром: XB, XD
```

Реальный пакет:

```
$ ./run.sh -p requests
Граф зависимостей пакета requests (глубина до 10, фильтр: —)

Пакеты по уровням (порядок обхода BFS):
  уровень 0: requests
  уровень 1: charset-normalizer, idna, urllib3, certifi

Зависимости:
  requests -> charset-normalizer, idna, urllib3, certifi
  charset-normalizer -> —
  idna -> —
  urllib3 -> —
  certifi -> —
...
```

Версии и списки зависимостей с реального PyPI могут отличаться
от примеров: пакеты обновляются.
