## 1. Описание

Консольная программа (CLI), которая строит граф зависимостей пакета
Python (pip). Готовые менеджеры пакетов и библиотеки для получения
зависимостей не используются — только стандартная библиотека Python
(`urllib`, `json`, `re`, `argparse`).

### Этапы

- **Этап 1. Минимальный прототип с конфигурацией** — параметры
  командной строки и их проверка с понятными сообщениями об ошибках.
- **Этап 2. Сбор данных** — получение прямых зависимостей пакета
  из репозитория PyPI по URL и вывод их на экран.

## 2. Как это работает

1. Программа запрашивает описание пакета через JSON API репозитория:
   `<URL>/<пакет>/json`, например `https://pypi.org/pypi/requests/json`.
2. Из ответа берётся поле `info.requires_dist` — список строк вида
   `idna<4,>=2.5` или `PySocks>=1.5.6; extra == "socks"`.
3. Каждая строка разбирается (формат PEP 508): имя пакета, ограничение
   версии, условие установки (маркер).
4. Зависимости с маркером `extra == ...` пропускаются: pip ставит их
   только по запросу (`pip install requests[socks]`).
5. Имена приводятся к единому виду (`Charset_Normalizer` →
   `charset-normalizer`), повторы убираются.

В тестовом режиме зависимости берутся из файла тестового репозитория.

### Модули

| Файл | Назначение |
|---|---|
| `src/main.py` | точка входа, вывод результата |
| `src/cli.py` | параметры командной строки и их проверка |
| `src/pypi_client.py` | запрос к репозиторию PyPI (urllib) |
| `src/requirements.py` | разбор строк зависимостей |
| `src/local_repo.py` | чтение файла тестового репозитория |
| `src/collector.py` | выбор источника и сбор зависимостей |

## 3. Параметры

| Параметр | Что задаёт | По умолчанию |
|---|---|---|
| `-p`, `--package ИМЯ` | имя анализируемого пакета (обязательный) | — |
| `-r`, `--repo URL_ИЛИ_ФАЙЛ` | URL репозитория или путь к файлу тестового репозитория | `https://pypi.org/pypi` |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием (файлом) | выключен |
| `-a`, `--ascii-tree` | вывод в виде ASCII-дерева (используется с этапа 5) | выключен |
| `-d`, `--max-depth N` | максимальная глубина анализа (используется с этапа 3) | `10` |
| `-f`, `--filter ПОДСТРОКА` | исключить пакеты с подстрокой в имени (используется с этапа 3) | нет |

### Ошибки

| Где | Ошибка |
|---|---|
| `--package` | не указан; пустой; недопустимые символы; в тестовом режиме — не большие латинские буквы |
| `--repo` | обычный режим — не `http://` / `https://`; тестовый режим — не указан или файла нет |
| `--ascii-tree`, `--test-mode` | передано значение (это флаги) |
| `--max-depth` | не целое число; меньше 1 |
| `--filter` | пустая строка |
| репозиторий | пакет не найден (HTTP 404); нет связи; ответ не в формате PyPI |
| тестовый файл | неверный формат строки; имя не из больших букв; пакет описан дважды; пакета нет в файле |

### Тестовый репозиторий

Файл, где пакеты называются большими латинскими буквами, `#` — комментарий:

```
A: B C
B: D
C: D E
D:
E:
```

Примеры: `test_repos/simple.txt`, `test_repos/cycle.txt` (с циклом),
`test_repos/broken.txt` (с ошибкой).

## 4. Запуск и тесты

Нужен Python 3.9+, сторонние библиотеки не нужны.

```bash
./run.sh -p requests          # прямые зависимости пакета из PyPI
./run.sh -p A -t -r test_repos/simple.txt   # из тестового репозитория
./run.sh -h                   # справка по параметрам
./run.sh test                 # запуск тестов
bash scripts/demo_deps.sh     # примеры работы этапа 2
bash scripts/demo_errors.sh   # примеры всех ошибок
```

В Windows без Git Bash: `run.bat -p requests`, `run.bat test`.

Тесты не требуют интернета: запросы к PyPI проверяются на локальном
HTTP-сервере с сохранёнными ответами (`tests/fixtures/pypi`).
Если интернета нет и на демонстрации, можно запустить такой сервер
вручную: `bash scripts/fake_pypi.sh`, а затем
`./run.sh -p requests -r http://localhost:8000/pypi`.
